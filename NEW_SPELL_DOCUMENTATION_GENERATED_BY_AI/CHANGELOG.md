# Changelog

All material changes to the specification are recorded here. Product release
history remains in the parent project and is not duplicated as document history.

## 0.1.0-draft.1 - 2026-07-18

- Established the generated next-generation documentation repository.
- Recorded the complete seven-file, 304-page legacy documentation evidence set.
- Preserved Language Reference 2.4.4 and Driver Development Manual 2.4.4 as
  external hash-pinned authorities.
- Defined normative system requirements, traceability, compatibility disposition,
  architecture decisions, web operating modes, procedure Git workflow, security,
  NIST SP 800-171 alignment, operations, reliability, verification and roadmap.
- Added a sole atomic requirement register with document-level allocation,
  machine-readable state contracts, commit-ordered/filtered stream semantics,
  controller client proof, per-execution sandbox isolation, PostgreSQL promotion
  authority, and pre-effect telemetry evidence binding.
- Added a mission-wide Satellite Assignment Authority that fences independent
  clusters, sites, restores, and legacy/new command paths with non-restorable
  authority incarnations and grant-bound credentials.
- Required externally anchored non-rollback assignment generations, explicit
  legacy-path adoption, one effect-enabled-path invariant, and a sole Effect
  Authorization Point with a linearizable one-use SAA attempt permit followed
  by transactional PostgreSQL permit and journal commit before send.
- Defined authority-incarnation stream epochs, opaque authorization projections,
  operation/attempt identity, read-only certainty applicability, and deterministic
  schedule restart reconciliation; drain first disables SAA effects and cannot
  dispatch queued work.
- Added an objective-level NIST SP 800-171/171A deployment assessment template
  while preserving organizational applicability, approval, and risk ownership.
- Added `MODE-023` through `MODE-027` for server-evaluated role-based startup,
  multi-role isolation, named control request, current-controller approval,
  requester responsibility acknowledgment, atomic higher-fence transfer,
  automatic mode projection, and complete correlated audit evidence.
- Added `DOC-011`, the controlled next-generation GUI User Manual source,
  versioned/outlined Draft PDF, four accessible concept wireframes, and reproducible
  publication tools.
- Added `NG-WP-00` evidence scaffolding: controlled allocation rules, a
  digest-bound 366-row implementation/evidence registry, a deterministic G0
  validator with unit coverage, a machine-readable readiness report, and a
  human decision package for startup, handover, audit, and `DOC-011`.
- Added a bounded Candidate v0.4 compatibility seed with 62 source-bound,
  25-field rows: 40 Driver Manual assertions and 22 Server Manual assertions.
  Added an explicit partial scope, digest-pinned reconciliation, a dedicated
  validator, and adversarial tests. All rows remain `Decomposed` and pending
  human approval; full seven-source and example coverage remains incomplete.
- Expanded that seed to seven authoritative source records and 257 rows by
  indexing the exact number, title, and page of all 195 Language Reference
  examples. Their bodies and oracles were not decomposed, no fixture or result
  evidence was produced, and their target increment remains unassigned pending
  `OD-008`. The four GUI, Development, Build, and GUI 4.0.2 catalogs still have
  zero detailed rows; the non-example Language, complete Driver, and complete
  Server catalogs remain incomplete. The record contains 195 `Indexed` and 62
  `Decomposed` rows, all pending human approval, and G0 remains `BLOCKED`.
- Superseded the partial local v0.4 gate model with the project-owner-approved
  local-only, synthetic non-CUI Candidate A profile. Organization-only
  approvals and proposed ADR acceptance remain broader-scope work, while the
  local gate retains exact scope/exclusion enforcement, synthetic-only
  resolution, bounded non-executing IR and mTLS credential separation,
  fail-closed authentication, migration/rollback, security, regression, and
  evidence-bound release gates. No operational or compliance claim is made.
- Prepared a candidate exhaustive seven-source compatibility disposition
  catalog covering all 304 pages and 195 Language Reference examples. Every
  row targets Candidate A or Deferred/`EXCLUDE` and has a planned test identity;
  excluded rows use static source and negative-scope evidence rather than
  executable fixtures or results. Independent source review and exact manifest
  binding remain required before Gate 0 can pass.
- Reconciled the Draft startup and handover narratives so current authorization
  and revocation always outrank an existing lease; the named requester's
  post-approval acknowledgement is a bounded Monitoring control-authority
  settlement; normal transfer uses one immutable lease-bounded deadline; forced
  takeover remains disabled pending human policy; workload and human-session
  decisions remain explicit; and durable local audit/outbox commit is separated
  from asynchronous publication and ingestion.
- Recorded structural G0 checks as passing while preserving the truthful
  `BLOCKED` gate state for ten Phase-entry decisions, 366 pending requirement
  approvals, six composite owners, 12 unnamed signers, five Proposed ADRs,
  incomplete exhaustive compatibility coverage and approval, and the unsigned
  Draft baseline.
- Separated candidate allocation from human approval evidence, bound allocation
  rows to the full normative record, made blocked validation nonzero by default,
  added cross-phase/gate and exact handover-package mappings, and expanded the
  G0 validator to 15 tests including approval/baseline spoof, approver,
  canonical-report, runtime, source-evidence pinning, empty-table, partial-seed,
  and future compatibility-gate integration cases.
- Declared ChatGPT 5.6 SOL as the project-provided AI assistance designation
  while retaining every technical, security, risk, compliance, and operational
  decision with accountable humans.
- Aligned the root and generated roadmaps to this repository as the
  authoritative next-generation implementation-scope specification while its
  Draft status and Gate G0 approval requirements remain in force.
- Recorded unresolved organization/mission values as owned decisions instead of
  inventing implementation defaults.
- Made no product code, operational authorization, compliance or release claim.
